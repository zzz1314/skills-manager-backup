# Markdown 转 Word

把已定稿的 Markdown 忠实转换为 `.docx`。内容准确性优先于视觉修饰，版式应便于屏幕阅读、批注和打印。

## 触发与授权

- 用户明确说“帮我转化为 DOC 文档”“转成 Word”“导出 DOCX”等，视为开始生成文件的授权，无需再次确认。
- 默认输出现代 Word 格式 `.docx`。只有用户明确要求旧版二进制 `.doc` 时，才说明兼容性限制并按可用工具处理，不能把 `.docx` 改扩展名冒充 `.doc`。
- 如果请求只是询问能否转换、讨论排版或内容尚未定稿，不生成文件。

## 确定输入

按以下顺序选择 Markdown 来源：

1. 用户在当前请求中指定的文件或附件。
2. 用户在当前任务中明确确认定稿的 Markdown 成果。
3. 当前任务里唯一且明显属于最终成果的 Markdown 文件。

来源唯一且明确时立即转换。存在多个候选、找不到源文件、无法判断是否定稿，或用户提到的文件与当前文件不一致时，只问一个简短的必要问题。不得静默拼接多个文件，也不得把聊天中的旧草稿当成最终稿。

保留 Markdown 原件，不就地改写。输出文件默认与源文件同名并使用 `.docx` 扩展名，放入任务的交付目录。若目标已存在，生成带版本号或时间戳的新文件，除非用户明确允许覆盖。

## 转换前盘点

转换前读取完整 Markdown 和其引用的本地资源，记录源文件的 SHA-256，并建立内容清单。至少盘点：

- 标题及标题层级；
- 正文段落、粗体、斜体、删除线和引用块；
- 有序列表的起始编号、重启位置、嵌套层级，以及无序列表层级；
- 每张表的行数、列数、表头和逐单元格文本；
- 代码块、行内代码、语言标签；
- 链接文本与目标地址；
- 图片路径、替代文本和题注；
- 脚注、引用和分隔关系；
- 行内公式与独立公式的原始表达式；
- 数字、日期、百分数、范围、正负号、上下标、单位和科学计数法。

若本地图片或引用资源缺失，先报告具体缺失项。不能用空白占位、猜测内容或擅自删除来完成转换。

## 创建 Word

使用可用的 `documents` 技能完成 DOCX 创建，并遵守其当前的依赖加载、公式处理、渲染和逐页检查要求。不要仅依赖一次性自动转换后直接交付。模板或 Word 参考文件存在时，以用户提供的模板为版式依据。

没有模板时采用克制、舒适的排版：

- 中文文档默认使用 A4 纵向和约 25 mm 页边距；其他语言或特定用途按受众调整。
- 正文优先使用已安装、适合长文阅读的字体，中文正文通常为宋体或思源宋体，英文和数字通常为 Times New Roman 或 Cambria。必须显式设置东亚字体和西文字体，避免字体回退导致混排跳动。
- 正文通常使用 10.5 至 12 pt，行距通常为 1.35 至 1.5 倍，并保留适度段后距。不能为压页数而把正文或表格缩得难以阅读。
- 标题全部使用 Word 标题样式并保持黑色，层级清楚。不能用手工加粗正文冒充标题。
- 列表使用 Word 原生编号或项目符号，保留起始编号、重启位置和嵌套层级。不能把有序列表统一重排为从 1 开始。
- 表格使用 Word 原生表格。表头跨页重复，列宽按内容分配，单元格允许自动增高，不能设置会截断文字的固定行高。
- 代码块使用等宽字体和可复制文本，避免用截图替代。
- 链接保留可点击目标，图片保持长宽比并在页面内完整显示。

除非用户要求编辑或重写，转换过程不得润色、删减、改写、翻译或纠正文稿。发现疑似错字、数据矛盾或公式问题时，保留原文并在交付说明中列出，不擅自修正。

## 公式处理

- 优先使用原生 Word 公式 OMML，使公式可编辑、可搜索和可复制。
- 只有当前环境没有可靠的 OMML 路径，且用户未要求公式可编辑时，才可使用高分辨率透明图像作为回退方案。
- 采用图像回退时，要保留原始 LaTeX 供核查，保持公式编号和正文引用关系，并明确说明公式不是原生 Word 公式。
- 不得在成品中留下原始 `$...$`、`$$...$$`、未解析命令或用普通字符近似上下标和分式。
- 对每个公式核对符号、上下标、分数线、根号、矩阵、括号、积分或求和上下限、希腊字母、公式编号和引用。

## 强制验收

交付前读取 [质量验收清单](references/quality-gates.md) 并完成全部适用项目。至少通过以下四道门槛：

1. 内容核对：逐项比对内容清单，核对全部数字、日期、百分数、单位和公式。
2. 结构核对：重新打开 DOCX，检查标题、段落、列表层级与起始编号、表格行列和链接目标。
3. 文件核对：确认 DOCX 可正常打开，内部资源完整，文件非空，源 Markdown 未改变。
4. 视觉核对：按 `documents` 技能要求把最新 DOCX 渲染为逐页 PNG，在 100% 比例检查每一页；修复重叠、裁切、缺字、表格断裂、公式模糊、孤行和异常空白后重新渲染。

只要任何适用门槛未通过，就不能声称转换完成。若环境限制导致某项无法验证，要交付当前可用结果并明确写出未验证项和影响，不能把预期效果写成已验证。

## 交付

只交付最终 `.docx`，除非用户要求查看清单、渲染页或中间文件。简要说明：

- DOCX 输出位置和使用的 Markdown 来源；
- 是否采用模板；
- 公式使用原生 OMML 还是图像回退；
- 已完成的内容、结构和逐页渲染检查；
- 任何保留的源文问题、字体替代或未验证限制。

不要声称能保证所有 Word、WPS 和 LibreOffice 版本像素级完全一致。应准确说明已在哪个渲染环境完成验证。
