# Markdown 转 Word 质量验收清单

仅在实际转换时读取并执行本清单。`不适用` 项应说明理由，不能直接跳过。

## 一 内容保真

- [ ] 记录源 Markdown 路径、SHA-256 和转换时间。
- [ ] 标题、正文和引文没有缺失、重复、改写或顺序变化。
- [ ] 粗体、斜体、删除线、行内代码和代码块语义得到保留。
- [ ] 全部数字逐项核对，包括负号、小数点、千位分隔、百分号、范围、日期和科学计数法。
- [ ] 全部单位逐项核对，包括大小写、空格、上标、下标和复合单位。
- [ ] 链接文本和目标地址一致，本地链接按交付场景可用。
- [ ] 图片与源文件对应，未拉伸，替代文本和题注得到保留。
- [ ] 引用、脚注和题注的标记与正文对应关系没有变化。

## 二 标题与列表

- [ ] 标题层级连续且与 Markdown 一致，没有仅靠外观模拟的标题。
- [ ] 有序列表数量、项目顺序、起始编号和重启位置一致。
- [ ] 嵌套列表层级、缩进和父子关系一致。
- [ ] 无序列表没有被误转为编号列表，复选框状态得到保留。
- [ ] 列表跨页时没有编号丢失、重复或意外重启。

## 三 表格

对每张表逐项检查：

- [ ] 表格数量、行数、列数和表头一致。
- [ ] 按阅读顺序逐单元格核对文字、数字、单位和空白单元格。
- [ ] 合并单元格关系没有改变，不能用空格模拟合并。
- [ ] 列宽符合内容长度，长文本正确换行，短值对齐合理。
- [ ] 行高可自动扩展，没有裁切文字。
- [ ] 跨页表格重复表头，续页不会造成列错位。
- [ ] 表题、表号和正文引用保持一致。

## 四 公式

对每个行内公式和独立公式逐项检查：

- [ ] 公式数量和出现顺序一致。
- [ ] 运算符、希腊字母、正负号和等号没有替换或丢失。
- [ ] 上下标、分式、根号、矩阵、向量、括号和上下限结构正确。
- [ ] 公式编号及正文引用关系一致。
- [ ] 行内公式不改变行距到影响阅读，独立公式未超出版心。
- [ ] 没有残留原始 Markdown 数学定界符或未解析 LaTeX 命令。
- [ ] 若使用图像公式，清晰度足够，背景透明，原始表达式留有可核查记录，并已向用户说明不可编辑。

## 五 版式与可读性

- [ ] 页面尺寸、方向和页边距符合用户要求或技能默认值。
- [ ] 中文、西文、数字和符号字体均已显式设置且实际可用。
- [ ] 正文、标题、表格和代码的字号适合正常屏幕及打印阅读。
- [ ] 段落间距、行距和缩进一致，没有密集墙状文本或异常大空白。
- [ ] 图片、表格、代码块和公式与相邻文字有清楚间距。
- [ ] 没有孤立标题、明显孤行、重叠、裁切、缺字或超出版心。
- [ ] 页眉、页脚和页码仅在需要时出现，位置一致。

## 六 结构与渲染验证

- [ ] 用文档库重新打开最终 DOCX，结构读取无错误。
- [ ] 标题数、表格数、图片数和公式数与转换前清单一致。
- [ ] DOCX 内部关系没有缺失，图片和链接目标有效。
- [ ] 最新版本已渲染为逐页 PNG。
- [ ] 已在 100% 比例查看每一页，不是抽样检查。
- [ ] 修复后重新渲染，并确认所检查的是最新 DOCX。
- [ ] Markdown 原文件的 SHA-256 在转换前后相同。

## 七 交付记录

- [ ] 最终只交付用户请求的文件，不混入 QA 临时文件。
- [ ] 说明源文件、输出文件、公式表示方式和验证结果。
- [ ] 保留的源文问题、字体替代或无法验证项已明确列出。
- [ ] 未使用“完全保证所有软件一致”等无法验证的绝对表述。
