# 岗位外部研究协议

在候选方向已经出现，且具体岗位事实会改变方向结论时使用。搜索结果是证据，不是结论。外部研究只服务于理解岗位，不进入实时求职执行。

## 目录

1. 触发条件
2. 搜索前生成研究问题

## 触发条件

- 用户已经提出或认可一个具体岗位、公司环境或业务线；
- 该岗位的职责、产出、验收、工作机制或核心成本已经成为当前判断的阻塞项；
- 用户提供具体 JD，需要判断其中的工作内容是否符合其方向预期；
- 两个具体岗位的本体差异会直接改变当前方向判断。
- 用户明确提出希望了解 HR、产品、销售等宽泛方向下的具体岗位或分支。

价值取舍、真实选择意愿和用户行为适配本身不联网。第一层默认不做泛化岗位搜索。HR、产品、销售等宽泛名称本身不构成联网触发条件；先做粒度提醒，只有用户明确需要了解下层岗位时才定向搜索分支。具体岗位事实成为节点 3、4、5 或方向报告的阻塞项时，仍可以在第一层进行一次定向岗位本体研究。

不要为了“多给几个方向”、丰富报告、寻找热门岗位或生成公司清单而联网。联网介入前先用一句话说明当前缺少什么岗位事实和研究目标；事实足以解除当前阻塞后立即停止搜索。

## 搜索前生成研究问题

不要泛搜“什么岗位适合校招生”。结合用户关心的条件生成任务：

研究宽泛岗位族时，先限定用户想了解的范围，只返回帮助他识别下一层的必要信息。不声称分类穷尽，不把客群、技术领域、工作重心和组织模式等不同分类轴混成同一层岗位列表。

```yaml
岗位:
用户重点关注:
需要研究:
  - 岗位为谁解决什么问题
  - 对什么核心产出负责，产出如何被验收
  - 为得到该产出，哪些工作动作和机制会反复发生
  - 这些核心动作推导出哪些必要要求和不可绕开成本
按需研究:
  - 会改变上述因果链的岗位分支或环境差异
  - 用户原始理由依赖的特定收益事实
  - 当前问题涉及进入条件时的专业门槛与前置条件
```

搜索查询不得包含用户姓名、学校全名、公司机密或其他个人信息。

不要搜索或追问当前职位数量、HC、招聘截止时间、投递渠道、城市选择、到岗日期、实习时长、每周出勤、简历通过率、笔面试反馈或 Offer 情况。用户主动询问这些内容时，说明它们属于独立的求职执行任务，先完成并结束当前方向诊断。

## 来源等级

### 一级：官方一手资料

公司官网、正式 JD、公司年报、业务介绍、政府或权威职业资料。用于判断公开职责、专业要求和业务定位。官方资料不能证明团队真实氛围或负面体验。

### 二级：多个独立从业者的一手经历

在职或离职员工分享、校招经验、行业访谈。用于发现实际工作方式、压力和官方描述遗漏。每个样本只代表其具体公司、团队和时期；至少比较多个独立来源。

### 三级：培训机构、聚合文章和泛岗位百科

只用于发现关键词和继续搜索，不能单独支持强结论。

## 研究输出

优先返回能够解除当前阻塞的最小因果链，不为了填满模板扩写成岗位百科：

```markdown
# 岗位研究：{岗位}

## 1. 存在理由与核心产出
## 2. 为产生结果而反复发生的核心动作
## 3. 由核心动作推导的必要要求与不可绕开成本
## 4. 会改变当前判断的分支或环境差异（如有）
## 5. 事实、从业者经验、推断与未知
```

对当前问题没有区分度的字段直接省略。为当前事实提供可访问来源、页面日期或信息时间。来源冲突时展示差异，不擅自平均。

## 证据标记

```yaml
判断:
性质: 事实/从业者经验/推断/未知
依据:
限制:
置信度: 高/中/低
```

## 禁止推断

- 不仅凭公司品牌判断岗位质量；
- 不用一篇经验帖代表整个岗位；
- 不把官方 JD 当作真实工作全貌；
- 不编造薪酬、强度、招聘数量和成功率；
- 不用招聘数量直接推导长期前景；
- 不把岗位与性格做一一对应；
- 不在没有内部资料时判断团队氛围、Leader 和晋升公平性；
- 不让搜索结果替用户完成价值选择。
- 不把岗位研究扩展成实时职位搜索、公司清单或投递方案。

## 公开信息不足时

明确说无法可靠判断，并生成验证问题，例如：

1. 入职后三个月主要负责什么？
2. 团队规模和过去一年人员变化如何？
3. 绩效如何计算？
4. 最近半年团队最重要的项目是什么？
5. 工作强度是日常状态还是阶段性项目？
6. 该岗位上一位员工的后续去向是什么？

没有联网工具时，请用户提供 JD 或已有岗位材料；不要假装已经检索。
